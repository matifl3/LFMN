===============================================================================
ESPECIFICACION DE REQUISITOS - LOW FUEL MOTORSPORT
===============================================================================

PROPOSITO
---------------------------------------------------------------------------
Plataforma web para una liga de sim racing. Gestiona pilotos, categorias,
campeonatos, carreras, sistema de puntuacion (Elo y Safety Rating),
setups, logros, recompensas y un flujo de incidentes resuelto por
comisarios.

ACTORES
---------------------------------------------------------------------------
- USUARIO   : piloto que participa de la liga.
- ADMIN     : administrador de la plataforma (usuarios, categorias,
              carreras, campeonatos, logros, anuncios).
- COMISARIO : encargado de analizar y resolver incidentes reportados.

LEVENDA DE PRIORIDAD
---------------------------------------------------------------------------
1 = Critico (sin esto el sistema no funciona / es el core del negocio)
2 = Alto    (funcionalidad principal, debe estar en la 1ra entrega)
3 = Medio   (mejora relevante, puede ir en una 2da entrega)
4 = Bajo    (complemento deseable)
5 = Cosmetico (ajuste menor de presentacion)

  Desc: El sistema debe permitir al admin el alta, baja y modificacion de
        carreras.
  Criterios:

    - Incluye edicion de fecha, hora, cupo y estado.
  Dependencias: RF-068

  Desc: El sistema debe permitir al admin ver el historial de carreras.

  Nota: -

  Desc: El sistema debe permitir al admin asignar pilotos a servidores.

      carrera.
    - Los pilotos ven su servidor (RF-027).
  Dependencias: RF-070
  Nota: -

RF-073 | Cierre automatico de inscripciones | Admin | Prioridad 1
  Desc: El sistema debe cerrar las inscripciones de una carrera 5 minutos
        antes de arrancar, automaticamente.
  Criterios:

    - Tras el cierre no se aceptan inscripciones nuevas.
  Dependencias: RF-070
  Nota: -

RF-074 | Cargar resultados de carrera | Admin | Prioridad 1
  Desc: El sistema debe permitir al admin cargar los resultados (posiciones

  Dependencias: RF-070, RF-040, RF-041
  Nota: [NUEVO] Cierra el hueco del flujo de datos (de donde salen los

REQUISITOS NO FUNCIONALES

NFR-001 | Seguridad de credenciales | Prioridad 1
  Desc: El sistema debe almacenar las contrasenas de forma segura y
        proteger el acceso.
  Criterios:
    - Las contrasenas se guardan con hash (ej. bcrypt).
    - Las sesiones expiran tras un tiempo de inactividad.
  Nota: [NUEVO]

NFR-002 | Autenticacion OAuth Steam | Prioridad 1
  Desc: El sistema debe integrarse con el sistema de autenticacion de
        Steam.
  Criterios:
    - El login de Steam usa el flujo OAuth oficial.
    - Los tokens se gestionan de forma segura.
  Nota: [NUEVO]

NFR-003 | Rendimiento | Prioridad 2
  Desc: El sistema debe responder de forma aceptable bajo carga normal.
  Criterios:
    - Las paginas principales cargan en menos de 3 segundos.
    - Las consultas de historiales y tablas soportan miles de registros.
  Nota: [NUEVO]

NFR-004 | Disponibilidad | Prioridad 2
  Desc: El sistema debe estar disponible durante los momentos criticos
        (carreras).
  Criterios:
    - El sistema soporta picos de acceso en horas de carrera.
  Nota: [NUEVO]

NFR-005 | Privacidad de datos | Prioridad 1
  Desc: El sistema debe proteger los datos personales de los usuarios.
  Criterios:
    - Solo roles autorizados ven datos sensibles.
    - Las contrasenas de servidores solo se exponen a inscriptos.
  Nota: [NUEVO]

NFR-006 | Compatibilidad | Prioridad 3
  Desc: El sistema debe funcionar en navegadores modernos y dispositivos
        comunes.
  Criterios:
    - Compatible con los navegadores mas usados (Chrome, Edge, Firefox,
      Safari).
    - Diseño responsive para movil y escritorio.
  Nota: [NUEVO]

NFR-007 | Auditabilidad | Prioridad 2
  Desc: El sistema debe registrar las acciones de cambios de Elo/SR y las
        decisiones de comisarios.
  Criterios:
    - Toda modificacion de Elo/SR queda con fecha, valor y responsable.
    - Toda resolucion de incidente queda con autor y timestamp.
  Nota: [NUEVO]
